## 2. Database Design (`conference_data.db`)

We will enforce relational constraints between users, press conferences, and the individual Q&A rounds.

### User Table (`users`)
Stores hashed authentication details.
* `id`: `INTEGER PRIMARY KEY AUTOINCREMENT`
* `username`: `TEXT UNIQUE NOT NULL`
* `hash`: `TEXT NOT NULL` (hashed using `werkzeug.security.generate_password_hash`)

### Conference Table (`conferences`)
Stores metadata and final generated output for each session.
* `id`: `INTEGER PRIMARY KEY AUTOINCREMENT`
* `user_id`: `INTEGER NOT NULL` (Foreign Key referencing `users.id` with cascade options)
* `screenshot_path`: `TEXT NOT NULL` (local filesystem path to the uploaded image)
* `initial_context`: `TEXT NOT NULL` (up to 200 character string)
* `headline`: `TEXT` (generated by AI, NULL during ongoing conference)
* `chronicle`: `TEXT` (generated by AI, NULL during ongoing conference)
* `created_at`: `DATETIME DEFAULT CURRENT_TIMESTAMP`

### Rounds Table (`rounds`)
Stores state and dialog logs for each of the 3 Q&A rounds.
* `id`: `INTEGER PRIMARY KEY AUTOINCREMENT`
* `conference_id`: `INTEGER NOT NULL` (Foreign Key referencing `conferences.id`)
* `round_number`: `INTEGER NOT NULL` (values: 1, 2, or 3)
* `question`: `TEXT NOT NULL` (AI generated reporter question)
* `answer`: `TEXT` (user/coach input, NULL until submitted)

## 3. Engineering Epics & Tasks

### Epic 1: Base Environment & DB Setup
Setting up the project scaffolding, database migrations, and utilities.
* [ ] Create `requirements.txt` containing dependencies.
* [ ] Create `schema.sql` database build script.
* [ ] Implement `services/db.py` to handle SQLite connections, dictionary mapping, and transaction isolation.
* [ ] Implement database initialization CLI command/helper (e.g., `init_db`).
* [ ] Create `.env.example` file for API key configurations.

### Epic 2: User Authentication System
A secure, session-based sign-in loop.
* [ ] Implement registration UI (`register.html`) and route controller (`routes/auth.py`).
* [ ] Implement password hashing and validation on backend using `werkzeug.security`.
* [ ] Implement login UI (`login.html`) and login route controller.
* [ ] Configure Flask sessions with secure cookies.
* [ ] Implement custom middleware/decorator (e.g., `@login_required`) to secure views and endpoints.
* [ ] Create logout endpoint.

### Epic 3: Press Conference Setup (Inputs & Media)
Handling uploads and form validations.
* [ ] Create dashboard UI (`setup.html`) with file input field and text box.
* [ ] Implement client-side drag-and-drop file listener and instantaneous image preview in JS.
* [ ] Add 200-character reactive countdown indicator in frontend and strict backend length checks.
* [ ] Implement secure file saving in `static/uploads/` directory, generating unique, hashed filenames to prevent collisions.

### Epic 4: AI Engine Integration & Q&A loop
Managing state transitions and connecting the Gemini SDK.
* [ ] Implement `services/gemini.py` wrapping the Google GenAI SDK.
* [ ] Create `POST /api/conference/start` endpoint:
  * Validate login session and inputs.
  * Initialize the new row in the `conferences` table.
  * Send the screenshot + initial comment to Gemini requesting **Question 1** (Sports Reporter tone).
  * Insert Question 1 in the `rounds` table and return it to frontend.
* [ ] Create `POST /api/conference/answer` endpoint:
  * Check current active round for the conference.
  * Update database with user's answer.
  * If round 1 or 2, request the next question from Gemini by passing the screenshot, context, and previous dialogue history. Save and return it.
  * If round 3, transition to the chronicle generation phase.

### Epic 5: Chronicle Generation & Newspaper Styling
Transforming the transcript into a stylized sports article.
* [ ] Implement the structured Gemini prompt in `services/gemini.py` to return JSON containing `headline` and `chronicle` using the dialogue transcript.
* [ ] Update `conferences` database entry with the final headline and chronicle.
* [ ] Design the frontend newspaper UI stylesheet:
  * Apply traditional newspaper layout (multiple text columns, serif typography, parchment color background).
  * Render the newspaper chronicle block dynamically.

### Epic 6: History Dashboard & Retro Modal
Viewing past conferences securely.
* [ ] Implement `/history` page route fetching past conferences for the logged-in user.
* [ ] Design the timeline / card grid UI.
* [ ] Create a JS listener that fetches the detailed dialog history (`rounds` table) for a conference when its card is clicked, displaying a modal with the full dialogue transcript and generated newspaper.
